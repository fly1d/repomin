# Support

Choose the route that matches the response you need:

| Need | Route |
| --- | --- |
| Help using ReproMin or understanding a result | [Q&A Discussion](https://github.com/fly1d/repomin/discussions/new?category=q-a) |
| Share a useful result, blocker, lesson, or workflow feedback | [Show and tell](https://github.com/fly1d/repomin/discussions/new?category=show-and-tell) |
| Reproducible behavior that appears incorrect | [Bug report](https://github.com/fly1d/repomin/issues/new?template=bug_report.md) |
| A focused capability, usability, or benchmark change | [Improvement proposal](https://github.com/fly1d/repomin/issues/new?template=feature_request.md) |
| Help making a public failure smaller | [Public-failure help](https://github.com/fly1d/repomin/issues/11) |
| Report a vulnerability | [Private security process](SECURITY.md) |

For a first public failure, share three things in the linked help thread:
the repository and revision, the command that fails, and a short error excerpt
showing what should remain. No installation, complete oracle design, or run
report is required. A maintainer checks reproducibility and helps define the
failure contract before reducing anything.

For self-service usage, see the [quick start](docs/QUICKSTART.md) and
[examples](docs/EXAMPLES.md). If you have already run ReproMin, share a reviewed
Markdown validation summary if available and what was useful or confusing. If
no report was created, a short redacted stage/error is enough. Do not retype
version, size and attempt fields. The [pilot guide](docs/REAL_FAILURE_PILOT.md)
covers running and reviewing a result.

Never post secrets, credentials, private URLs, proprietary source, customer
data, confidential logs, or security vulnerabilities in a public conversation.
